**Mục tiêu:** đi từ một cuộc tấn công SSH đến việc phát hiện brute-force bằng log.

```text
SSH connection
      ↓
Authentication
      ↓
Failed login
      ↓
Log entry
      ↓
Regex / grep
      ↓
Extract IP
      ↓
Count attempts
      ↓
Detect brute-force
```

# Phần 1: SSH và Socket

## 1.1. SSH là gì?

**SSH** = Secure Shell.

SSH cho phép một máy **client** kết nối tới một máy **server** để:

- đăng nhập từ xa
- chạy lệnh (command)
- truyền file
- quản lý server

**Mô hình:**

```text
+-------------+        TCP        +-------------+
| SSH Client  | ----------------> | SSH Server  |
|   Ubuntu    |                   |   Ubuntu    |
+-------------+                   +-------------+

                         sshd : 22
```

- SSH server thường lắng nghe trên cổng **TCP/22**.
- Process của server thường có tên **sshd**.

## 1.2. Socket là gì?

**Socket** là một điểm cuối (endpoint) trong giao tiếp mạng, được xác định bởi:

```text
IP + Port + Protocol
```

Ví dụ: `192.168.1.50:22/TCP`

Một kết nối TCP có thể biểu diễn như sau:

```text
Client                          Server
------------------------------------------------
192.168.1.100:43001   --->   192.168.1.50:22
                TCP (SSH)
```

Trong log của W01-D03 có các cổng:

```text
port 42111
port 42112
port 42113
```

> Đây thường là **cổng nguồn (source port) của client**, không phải cổng của SSH server.

Xét dòng log:

```text
Failed password for root from 192.168.1.50 port 42111 ssh2
```

Có thể đọc như sau:

| Thông tin   | Giá trị      |
| ----------- | ------------ |
| User        | root         |
| Source IP   | 192.168.1.50 |
| Source port | 42111        |
| Protocol    | SSH          |

Trong khi đó, SSH server vẫn đang lắng nghe trên **TCP/22**.

## 1.3. Kiểm tra socket trên Ubuntu

```bash
ss -tuln
```

Ý nghĩa các tùy chọn:

| Tùy chọn | Ý nghĩa                                 |
| -------- | --------------------------------------- |
| `-t`     | TCP                                     |
| `-u`     | UDP                                     |
| `-l`     | chỉ hiện socket đang lắng nghe (listen) |
| `-n`     | hiện số (cổng, IP), không phân giải tên |

Ví dụ output:

```text
LISTEN 0 128 0.0.0.0:22 0.0.0.0:*
```

> Dòng trên nghĩa là có một service đang **LISTEN** trên TCP port 22.

## 1.4. Cài đặt và kiểm tra SSH server

**Bước 1** — Kiểm tra trạng thái dịch vụ:

```bash
systemctl status ssh
```

**Bước 2** — Nếu chưa có, cài đặt:

```bash
sudo apt install openssh-server
```

**Bước 3** — Bật và chạy dịch vụ:

```bash
sudo systemctl enable --now ssh
```

**Bước 4** — Kiểm tra cổng 22 đã lắng nghe chưa:

```bash
ss -tln | grep ':22'
```

Kết quả mong đợi:

```text
LISTEN ... :22 ...
```

## 1.5. Xem process sshd

```bash
ps aux | grep '[s]shd'
```

**Vì sao dùng `'[s]shd'` thay vì `sshd`?**

Nếu dùng:

```bash
ps aux | grep sshd
```

thì chính process `grep sshd` cũng xuất hiện trong kết quả, vì dòng lệnh của nó chứa chuỗi `sshd`. Pattern `[s]shd` vẫn khớp với `sshd`, nhưng dòng lệnh của `grep` lúc này chứa `[s]shd` nên không tự khớp với chính nó.

# Phần 2: Cơ chế brute-force SSH

## 2.1. Đăng nhập SSH bình thường

```text
Client
  │
  │ TCP connection
  ↓
Server:22
  │
  │ SSH handshake
  ↓
Authentication
  │
  ├── Success → session
  │
  └── Failure → log event
```

## 2.2. Brute-force (tấn công vét cạn)

> Thử lần lượt tất cả các khả năng cho đến khi tìm được kết quả đúng.

```text
Attacker
  │
  ├── password 1 → FAIL
  ├── password 2 → FAIL
  ├── password 3 → FAIL
  ├── password 4 → FAIL
  ├── password 5 → FAIL
  │
  └── password N → ?
```

> Nếu các lần thử thất bại xảy ra liên tục trong thời gian ngắn, SOC có thể xây dựng detection rule để phát hiện.

## 2.3. Password spraying

**Password spraying** là kiểu tấn công dùng **1 password** thử trên **nhiều tài khoản** khác nhau.

So sánh với brute-force:

| Kiểu tấn công     | Cách thử                      |
| ----------------- | ----------------------------- |
| Brute-force       | 1 account, thử nhiều password |
| Password spraying | 1 password, thử nhiều account |

**Brute-force** (một account):

```text
root
├── password1
├── password2
├── password3
└── password4
```

**Password spraying** (một password):

```text
Password123
├── root
├── admin
├── test
├── hieu
└── user
```

Vì vậy khi phân tích log, cần tự đặt câu hỏi:

> Ai → thử account nào → từ IP nào → trong khoảng thời gian nào?

## 2.4. Vì sao log quan trọng?

Một cuộc tấn công SSH diễn ra trên mạng, nhưng để lại **dấu vết (artifact)** trong hệ thống:

```text
Network
   ↓
SSH connection
   ↓
sshd
   ↓
Authentication
   ↓
auth log
```

Ví dụ một dòng log:

```text
Failed password for root from 192.168.1.50
```

Khi SOC viết báo cáo, cần ghi lại tối thiểu:

- Source IP
- Username
- Time
- Authentication result

# Phần 3: Regex và Pipeline

**Regex** (biểu thức chính quy) là cách mô tả một **mẫu (pattern)** trong văn bản.

## 3.1. Regex dùng để làm gì?

Giả sử có dòng log:

```text
Oct 03 10:01:01 server sshd[2001]: Failed password for root from 192.168.1.50 port 41001 ssh2
```

Để tìm các dòng chứa "Failed password", dùng `grep`:

```bash
grep "Failed password" ssh_bruteforce.log
```

Nhưng để tìm **mọi địa chỉ IP**, ví dụ:

```text
192.168.1.50
10.10.10.20
172.16.0.15
```

ta cần một pattern mô tả dạng:

```text
số.số.số.số
```

> Đây chính là lúc cần dùng regex.

## 3.2. Các ký hiệu regex cơ bản

Tóm tắt nhanh:

| Ký hiệu | Ý nghĩa                     |
| ------- | --------------------------- |
| `.`     | 1 ký tự bất kỳ              |
| `^`     | bắt đầu dòng                |
| `$`     | cuối dòng                   |
| `*`     | lặp 0 hoặc nhiều lần        |
| `?`     | xuất hiện 0 hoặc 1 lần      |
| `[ ]`   | 1 ký tự trong tập cho trước |
| `[0-9]` | 1 chữ số từ 0 đến 9         |

> Các ký hiệu như `+`, `?`, `{n}` cần dùng với `grep -E` (extended regex).

### Dấu `.` — một ký tự bất kỳ

```bash
grep "c.t" file
```

Có thể khớp với:

```text
cat
cut
```

### Dấu `^` — bắt đầu dòng

Giả sử có 3 dòng log:

```text
Oct 03 10:01:01 server sshd[2001]: Failed password for root from 192.168.1.50 port 41001 ssh2
Oct 03 10:01:02 server sshd[2002]: Failed password for root from 192.168.1.50 port 41002 ssh2
Oct 03 10:01:03 server sshd[2003]: Failed password for root from 192.168.1.50 port 41003 ssh2
```

```bash
grep "^Oct" ssh_bruteforce.log
```

→ Trả về cả 3 dòng, vì cả 3 đều **bắt đầu** bằng "Oct".

Ngược lại:

```bash
grep "^Failed" ssh_bruteforce.log
```

→ Không trả về dòng nào, vì không dòng nào **bắt đầu** bằng "Failed".

### Dấu `$` — cuối dòng

```bash
grep "ssh2$" ssh_bruteforce.log
```

→ Trả về cả 3 dòng, vì cả 3 đều **kết thúc** bằng "ssh2".

Ngược lại:

```bash
grep "Failed$" ssh_bruteforce.log
```

→ Không trả về dòng nào, vì không dòng nào **kết thúc** bằng "Failed".

### Dấu `*` — lặp 0 hoặc nhiều lần

Dấu `*` áp dụng cho ký tự đứng ngay trước nó.

```bash
grep "fo*" file.log
```

Có thể khớp với:

```text
f
fo
foo
fooo
fooooo
```

### Dấu `[ ]` — một trong các ký tự trong ngoặc

```bash
grep "c[au]t" file.log
```

Có thể khớp với:

```text
cat
cut
```

(nghĩa là `a` **hoặc** `u`)

### Dấu `[0-9]` — một chữ số

Giả sử có file `log.txt`:

```text
Oct 5 10:15:32 server sshd[1234]: Failed password for root from 192.168.1.10 port 54321 ssh2
Oct 5 10:15:35 server sshd[1235]: Failed password for admin from 10.0.0.5 port 44444 ssh2
Oct 5 10:15:40 server sshd[1236]: Accepted password for hieu from 172.16.0.2 port 55555 ssh2
```

```bash
grep '[0-9]' log.txt
```

→ Trả về cả 3 dòng, vì dòng nào cũng có chữ số.

Tương tự có `[a-z]` (chữ thường) và `[A-Z]` (chữ hoa).

Một số biến thể thường gặp:

| Regex      | Ý nghĩa                 |
| ---------- | ----------------------- |
| `[0-9]`    | đúng 1 chữ số           |
| `[0-9]+`   | 1 chữ số trở lên        |
| `[0-9]{4}` | đúng 4 chữ số liên tiếp |
| `[0-9]*`   | 0 hoặc nhiều chữ số     |

### Dấu `?` — xuất hiện 0 hoặc 1 lần

```bash
grep -E "ab?c" file.log
```

Có thể khớp với:

```text
ac
abc
```

> Ký tự `b` có thể có hoặc không.

## 3.3. Regex nhận diện địa chỉ IP

Để nhận diện địa chỉ như `192.168.1.50`, ta dùng:

```bash
grep -E '[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+' ssh_bruteforce.log
```

> Dấu `\.` dùng để chỉ **đúng ký tự dấu chấm**. Nếu chỉ viết `.` thì nó sẽ khớp với 1 ký tự bất kỳ (xem mục 3.2), nên phải thêm `\` phía trước để "thoát" ý nghĩa đặc biệt.

## 3.4. Trích xuất danh sách IP

Tùy chọn `-o` giúp `grep` **chỉ in phần được khớp**, thay vì in cả dòng.

Giả sử file `ssh_bruteforce.log` có nội dung:

```text
Oct 03 10:01:01 server sshd[2001]: Failed password for root from 192.168.1.50 port 41001 ssh2
Oct 03 10:01:02 server sshd[2002]: Failed password for root from 192.168.1.50 port 41002 ssh2
Oct 03 10:01:03 server sshd[2003]: Failed password for root from 192.168.1.50 port 41003 ssh2
Oct 03 10:01:04 server sshd[2004]: Failed password for admin from 192.168.1.50 port 41004 ssh2
Oct 03 10:01:05 server sshd[2005]: Failed password for root from 10.10.10.20 port 42001 ssh2
Oct 03 10:01:06 server sshd[2006]: Failed password for root from 10.10.10.20 port 42002 ssh2
Oct 03 10:01:07 server sshd[2007]: Failed password for test from 10.10.10.20 port 42003 ssh2
Oct 03 10:01:08 server sshd[2008]: Failed password for admin from 172.16.0.15 port 43001 ssh2
Oct 03 10:01:09 server sshd[2009]: Failed password for admin from 172.16.0.15 port 43002 ssh2
Oct 03 10:01:10 server sshd[2010]: Accepted password for hieu from 192.168.1.100 port 44001 ssh2
```

Chạy:

```bash
grep -oE '[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+' ssh_bruteforce.log
```

Output:

```text
192.168.1.50
192.168.1.50
192.168.1.50
192.168.1.50
10.10.10.20
10.10.10.20
10.10.10.20
172.16.0.15
172.16.0.15
192.168.1.100
```

## 3.5. Pipeline đếm IP tấn công nhiều nhất

Các bước xử lý:

```text
grep "Failed password"
        ↓
Chỉ lấy các lần SSH login thất bại
        ↓
grep -oE "IP regex"
        ↓
Chỉ lấy địa chỉ IP
        ↓
sort
        ↓
Đưa các IP giống nhau nằm cạnh nhau
        ↓
uniq -c
        ↓
Đếm số lần xuất hiện của mỗi IP
        ↓
sort -nr
        ↓
IP xuất hiện nhiều nhất lên đầu
```

Lệnh hoàn chỉnh:

```bash
grep "Failed password" ssh_bruteforce.log | grep -oE '[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+' | sort | uniq -c | sort -nr
```

Output:

```text
4 192.168.1.50
3 10.10.10.20
2 172.16.0.15
```

# Phần 4: sed và awk cơ bản

## 4.1. sed là gì?

**sed** = Stream Editor.

> Đọc văn bản từng dòng, rồi tìm, thay thế, xóa hoặc chỉnh sửa dòng đó.

**Cấu trúc:**

```bash
sed 's/OLD/NEW/' file
```

Trong đó:

| Thành phần | Ý nghĩa               |
| ---------- | --------------------- |
| `s`        | substitute (thay thế) |
| `OLD`      | nội dung cần tìm      |
| `NEW`      | nội dung thay thế     |

## 4.2. sed không sửa file gốc theo mặc định

```bash
sed 's/root/admin/' ssh_bruteforce.log
```

> Lệnh này chỉ **in kết quả đã thay đổi ra màn hình**; nội dung file gốc vẫn giữ nguyên.

Nếu muốn sửa trực tiếp vào file, dùng `-i`:

```bash
sed -i 's/root/admin/' ssh_bruteforce.log
```

> ⚠️ Khi làm SOC, không tùy tiện dùng `-i` trên log thật. Log là **evidence (chứng cứ)**, không nên tự ý thay đổi.

## 4.3. Các lệnh sed cơ bản

**Thay thế:**

```bash
sed 's/root/admin/' file.log # thay root bằng admin
```

**Xóa dòng:**

```bash
sed '/Accepted/d' file.log # xóa các dòng chứa "Accepted"
```

> `d` = delete

**Chỉ xem dòng cụ thể:**

```bash
sed -n '1p' ssh_bruteforce.log
```

- `-n` : không tự động in tất cả các dòng
- `'1p'` : chỉ in dòng số 1

Ví dụ: in từ dòng 1 đến dòng 3:

```bash
sed -n '1,3p' ssh_bruteforce.log
```

## 4.4. SOC dùng sed để làm gì?

Giả sử có dòng log:

```text
Failed password for root from 192.168.1.50
```

Muốn thay username để tạo dữ liệu test:

```bash
sed 's/root/admin/g' ssh_bruteforce.log
```

> Chữ `g` (global) giúp thay **mọi** vị trí khớp trong dòng. Nếu không có `g`, `sed` chỉ thay vị trí khớp **đầu tiên** của mỗi dòng.

Trong phân tích log thực tế, `sed` thường nằm ở bước làm sạch dữ liệu:

```text
raw log
   ↓
sed làm sạch / chuẩn hóa
   ↓
awk phân tích field
   ↓
sort / uniq
   ↓
alert
```

## 4.5. awk là gì?

**awk** là công cụ xử lý văn bản theo **cột (field)** và **điều kiện**.

Giả sử có dòng log:

```text
Oct 03 10:01:01 server sshd[2001]: Failed password for root from 192.168.1.50 port 41001 ssh2
```

`awk` mặc định tách dòng theo khoảng trắng thành các field:

| Field | Giá trị      |
| ----- | ------------ |
| `$1`  | Oct          |
| `$2`  | 03           |
| `$3`  | 10:01:01     |
| `$4`  | server       |
| `$5`  | sshd[2001]:  |
| `$6`  | Failed       |
| `$7`  | password     |
| `$8`  | for          |
| `$9`  | root         |
| `$10` | from         |
| `$11` | 192.168.1.50 |
| `$12` | port         |
| `$13` | 41001        |
| `$14` | ssh2         |

Lấy username:

```bash
awk '{print $9}' ssh_bruteforce.log
```

Lấy IP:

```bash
awk '{print $11}' ssh_bruteforce.log
```

## 4.6. Kết hợp grep và awk

Chỉ lấy IP của những lần đăng nhập **thất bại**:

```bash
grep "Failed password" ssh_bruteforce.log | awk '{print $11}'
```

## 4.7. Lọc theo điều kiện với awk

**Cú pháp:**

```bash
awk 'điều_kiện {hành_động}' file.log
```

Ví dụ: chỉ lấy dòng có IP `192.168.1.50`:

```bash
awk '$11 == "192.168.1.50" {print}' ssh_bruteforce.log
```

## 4.8. In nhiều field cùng lúc

Muốn xem cả IP và username:

```bash
awk '{print $11, $9}' ssh_bruteforce.log
```

Có thể thêm chữ để dễ đọc:

```bash
awk '{print "IP:", $11, "Username:", $9}' ssh_bruteforce.log
```

## 4.9. Ví dụ tổng hợp

**Câu hỏi:** IP nào đang brute-force vào tài khoản `root`?

```bash
awk '$9 == "root" {print $11}' ssh_bruteforce.log | sort | uniq -c | sort -nr
```

## 5.1. Biến đặc biệt: $0, NF, NR

| Biến | Ý nghĩa                     |
| ---- | --------------------------- |
| `$0` | toàn bộ dòng hiện tại       |
| `NF` | số field của dòng hiện tại  |
| `NR` | số thứ tự của dòng hiện tại |

### `$0` — in nguyên dòng

> In cả dòng, không chỉ riêng từng field.

```bash
awk '$9 == "root" {print $0}' ssh_bruteforce.log
```

→ In ra các dòng có `$9` bằng `root`.

### `NF` — số field của mỗi dòng

```text
14
```

```bash
awk '{print NR, $0}' ssh_bruteforce.log
```

## 5.2. Khi chưa biết IP nằm ở field nào

**In số thứ tự và giá trị của từng field:**

```bash
awk '{for (i=1; i<=NF; i++) print i, $i}' ssh_bruteforce.log
```

## 5.3. Toán tử so sánh

| Toán tử | Ý nghĩa           |
| ------- | ----------------- |
| `==`    | bằng              |
| `!=`    | khác              |
| `>`     | lớn hơn           |
| `<`     | nhỏ hơn           |
| `>=`    | lớn hơn hoặc bằng |
| `<=`    | nhỏ hơn hoặc bằng |

## 5.4. Regex trong awk

**Cú pháp:**

```bash
awk '$field ~ /regex/ {action}' file.log
```

Ví dụ: tìm các IP bắt đầu bằng `192.168`:

```bash
awk '$11 ~ /^192\.168/ {print $0}' ssh_bruteforce.log
```

**Khi không biết field nào chứa thông tin:**

```bash
awk '$0 ~ /Failed password/ {print $0}' ssh_bruteforce.log
```

Cách viết ngắn gọn tương đương:

```bash
awk '/Failed password/ {print $0}' ssh_bruteforce.log
```

→ Tìm các dòng **chứa** "Failed password".

Ngược lại, tìm các dòng **không chứa** "Failed password" (dùng `!~`):

```bash
awk '$0 !~ /Failed password/ {print $0}' ssh_bruteforce.log
```

**Regex trên 1 field:**

```bash
awk '$9 ~ /^r/' ssh_bruteforce.log
```

→ Tìm các dòng có username bắt đầu bằng `r` (ví dụ: `root`).

**Regex kết hợp điều kiện:**

Ví dụ: các lần Failed password từ mạng `192.168.x.x`:

```bash
awk '$6 == "Failed" && $11 ~ /192\.168/ {print $0}' ssh_bruteforce.log
```

**Khi không biết IP nằm ở field nào**, có thể dùng regex trực tiếp trên cả dòng:

```bash
awk '/Failed/ && /192\.168/ {print $0}' ssh_bruteforce.log
```

## 5.5. Field separator: FS và OFS

### FS — ký tự phân tách field của đầu vào

Mặc định `awk` tách field theo khoảng trắng. Nếu dữ liệu dùng dấu phân tách khác, dùng `-F`.

Ví dụ có dòng: `user,192.168.1.50,failed,ssh`

```bash
awk -F',' '{print $1}' file.log
```

Output:

```text
user
```

### OFS — ký tự phân tách field của đầu ra

Khi chạy:

```bash
awk '{print $11, $9}' ssh_bruteforce.log
```

Output:

```text
192.168.1.50 root
192.168.1.50 root
192.168.1.50 root
192.168.1.50 admin
10.10.10.20 root
10.10.10.20 root
10.10.10.20 test
172.16.0.15 admin
172.16.0.15 admin
192.168.1.100 hieu
```

Nếu đặt `OFS` trong khối `BEGIN`:

```bash
awk 'BEGIN {OFS=" -> "} {print $11, $9}' ssh_bruteforce.log
```

Output:

```text
192.168.1.50 -> root
192.168.1.50 -> root
192.168.1.50 -> root
192.168.1.50 -> admin
10.10.10.20 -> root
10.10.10.20 -> root
10.10.10.20 -> test
172.16.0.15 -> admin
172.16.0.15 -> admin
192.168.1.100 -> hieu
```

## 5.6. BEGIN và END

Cấu trúc một chương trình `awk`:

```text
BEGIN {
    # chạy 1 lần, trước khi đọc file
}

{
    # chạy cho từng dòng
}

END {
    # chạy 1 lần, sau khi đọc hết file
}
```

Ví dụ: đếm số lần đăng nhập thất bại:

```bash
awk 'BEGIN {count = 0} /Failed/ {count++} END {print "Failed attempts:", count}' ssh_bruteforce.log
```

## 5.7. Tự đếm bằng awk

`awk` có thể tự đếm theo từng IP mà **không cần** `sort | uniq -c`:

```bash
awk '/Failed password/ {count[$11]++}
END {
    for (ip in count)
        print count[ip], ip
}' ssh_bruteforce.log
```

> `count[$11]++` dùng IP (`$11`) làm khóa trong mảng và tăng bộ đếm của khóa đó lên 1 cho mỗi dòng khớp.
