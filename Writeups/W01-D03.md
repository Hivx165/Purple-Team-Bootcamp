# Phần 1 - grep Mastery

## 1. grep là gì ?

- là chương trình dùng để tìm các dòng chứa một mẫu (pattern) trong :
  - file văn bản
  - log hệ thống
  - hoặc đầu ra của lệnh khác

(hình dung `grep` giống `ctrl + F`)

ví dụ bạn có file log

```bash
INFO User admin logged in
ERROR Database connection failed
WARNING Disk almost full
ERROR Invalid password
```

muốn tìm tất cả các dòng chứa `ERROR` :

input:

```bash
grep "ERROR" app.log
```

output :

```bash
ERROR Database connection failed
ERROR Invalid password
```

**cú pháp** : `grep [option] "pattern" file`

trong đó :

| Thành phần | Ý nghĩa                      |
| ---------- | ---------------------------- |
| grep       | chương trình tìm kiếm        |
| [option]   | tùy chọn                     |
| "pattern"  | chuỗi hoặc biểu thức cần tìm |
| file       | file cần tìm                 |

giả sử file "app.log" có nội dung :

```bash
INFO User admin logged in
ERROR Database connection failed
INFO File uploaded
WARNING Disk almost full
ERROR Invalid password
INFO Logout successful
```

khi sử dụng lệnh : `grep "ERROR" app.log` -> grep đọc từng dòng, nếu có "ERROR" thì in ra, không thì bỏ qua

## 2. option `-i` - không phân biệt chữ hoa hay chữ thường

khi sử dụng lệnh : `grep -i "ERROR" app.log`

> kết quả :

    - error
    - ERROR
    - Error

dùng khi : SOC thường dùng khi log từ nhiều hệ thống không thống nhất cách viết

## 3. option `-n` hiển thị pattern ở dòng số bao nhiêu :

input:

```bash
grep -n "ERROR" app.log
```

ouput :

```bash
2:ERROR Database connection failed
5:ERROR Invalid password
```

## 4. option `-c` - số kết quả

input:

```bash
grep -c "ERROR" app.log
```

ouput :

```bash
2
```

## 5. option `-v` - hiển thị những dòng không chứa pattern

input :

```bash
grep -v "ERROR" app.log
```

output:

```bash
INFO User admin logged in
INFO File uploaded
WARNING Disk almost full
INFO Logout successful
```

## 6. option `-r` - tìm pattern trong nhiều file

Tạo thư mục:

```bash
mkdir logs
cp app.log logs/system.log
cp app.log logs/auth.log
```

input :

```bash
grep -r "ERROR" logs/
```

=> grep sẽ tìm hết các file trong /logs

=> lệnh BlueTeam dùng rất nhiều

## 7. Regex cơ bản

**^ - bắt đầu dòng :**

lệnh : `grep "^ERROR" app.log`

ouput :

```bash
ERROR Database connection failed
ERROR Invalid password
```

=> chỉ lấy khi "ERROR" đứng đầu dòng

**$ - kết thúc dòng :**

lệnh : `grep "failed$" app.log`

output :

```bash
ERROR Database connection failed
```

**. - đại diện cho 1 kí tự bất kỳ**

lệnh : `grep "ERRO." app.log`

có thể : ERROR, ERROx,...

## 8. grep -E

`-E` là biểu thức chính quy mở rộng

lệnh : `grep -E "ERROR|WARNING" app.log`

=> dùng như OR

output :

```bash
ERROR Database connection failed
WARNING Disk almost full
ERROR Invalid password
```

## 9. grep với Pipe

đây là cách dùng nhiều trong thực tế

vd :

```bash
cat app.log | grep "ERROR"
```

`|` có thể hiểu là lấy output của lệnh bên trái làm input cho lệnh bên phải

lệnh trên tương tự với :

```bash
grep "ERROR" app.log
```

# Phần 3 : Pipe & Redirection

## 1. Tư duy cốt lõi

command A

|

|
v

Command C

```bash
cat /etc/passwd | grep "/bin/bash"
```

## 2. Ba luồng quan trọng: stdin / stdout / stderr

linux process thường có 3 stream:

              PROCESS
                 │
       ┌─────────┼─────────┐
       ▼         ▼         ▼
     stdin     stdout    stderr
      0          1          2
       │          │          │
      input     output      error

**`stdin` - file descriptor 0**
input đi vào chương trình

ví dụ :

```bash
cat < users.txt
```

> `users.txt` trở thành input của `cat`

**`stdout` - file descriptor 1**
output bình thường của chương trình

ví dụ :

```bash
ls
```

> danh sách file được in ra terminal -> đó là `stdout`

**`stderr` - file descriptor 2**

```bash
ls /abcxyz
```

có thể nhận :
`ls: cannot access '/abcxyz': No such file or directory`

> đây là `stderr`

## 3. Pipe

cú pháp :

```bash
command1 | command2
```

**Ý nghĩa**

> lấy `stdout` của command1 làm `stdin` cho command2

vd :

```bash
ls /ect | grep ssh
```

Luồng :

ls /etc
│
│ stdout
▼
|
▼
grep ssh
│
▼
chỉ giữ dòng có "ssh"

## 4. Có thể nối nhiều pipe

ví dụ :

```bash
ps aux | grep ssh | head
```

**vd SOC :**

giả sử log có nhiều dòng :

có thể dùng

```bash
grep "Failed password" /var/log/auth.log
```

có thể tiếp tục

```bash
grep "Failed password" /var/log/auth.log | head
```

hoặc

```bash
grep "Failed password" /var/log/auth.log | wc -l
```

> tìm các lần đăng nhập thất bại SSH thất bại -> đếm số dòng

## 5. Redirection `>`

`>` dùng để : ghi stdout vào file

vd :

```bash
ls /etc > etc_list.txt
```

> thay vì in ra terminal thì kết quả được ghi vào etc_list.txt

> nếu file đã tồn tại thì khi thực hiện lệnh, nội dung cũ của file sẽ bị ghi mất và ghi đè bằng file mới

## 6. Append `>>`

dùng đề thêm vào cuối file thay vì ghi đè

```bash
>    # ghi mới / ghi đè
>>   # thêm vào cuối
```

## 7. Redirect stderr với `2>`

như trên :
0 = stdin
1 = stdout
2 = stderr

Redirect vào file : `2>`

ví dụ :

```bash
ls /abc 2> error.txt
```

> terminal sẽ không hiện lỗi nữa

kiểm tra:

```bash
cat error.txt
```

> thấy thông báo lỗi được ghi trong file

**Append error**

```bash
ls /abc 2>> error.log
```

> lỗi sẽ được thêm vào cuối file

## 8. Một số ví dụ quan trọng

khi chạy :

```bash
ls /etc /abc
```

sẽ thấy :
/etc:
...
...
ls: cannot access '/abcxyz': No such file or directory

ở đây:
/etc/... → stdout
ls: cannot access... → stderr

bây giờ :

```bash
ls /etc /abcxyz > output.txt
```

khi dùng :

```bash
cat output.txt
```

> chỉ thấy nội dung của /etc, nhưng không thấy error vì `> output.txt` chỉ redirect stdout còn stderr vẫn đi ra terminal

## 9. Redirect cả stdout và stderr

cú pháp :

```bash
command &> output.txt
```

ví dụ:

```bash
ls /etc /abc &> result.txt
```

> cả stdout và stderr đều được ghi vào

cách viết tương đương :

```bash
command > output.txt 2>&1
```

## 10. /dev/null

> thùng rác của linux

ví dụ :

```bash
command 2>/dev/null
```

> bỏ toàn bộ lỗi đi (đẩy toàn bộ stderr vào /dev/null)

## 11. Đây là một pattern rất quan trọng

vd tìm SUID :

```bash
find / -perm -4000 -type f 2>dev/null
```

luồng :

find /
│
├── kết quả tìm được ──────────→ stdout → terminal
│
└── Permission denied ─────────→ stderr → /dev/null

## 12. kết hợp Pipe + Redirection

ví dụ :

```bash
grep "Failed password" /var/log/auth.log | wc -l > failed_count.txt
```

luồng :

auth.log
│
▼
grep "Failed password"
│
│ matching lines
▼
wc -l
│
│ số lượng
▼
failed_count.txt

## Cheat Sheet part 3

| Cú pháp     | Ý nghĩa                           |
| ----------- | --------------------------------- |
| `A \| B`    | Output A → input B                |
| `>`         | Ghi stdout vào file, ghi đè       |
| `>>`        | Ghi stdout vào cuối file          |
| `2>`        | Ghi stderr vào file               |
| `2>>`       | Append stderr                     |
| `&>`        | Ghi cả stdout + stderr            |
| `2>&1`      | Đưa stderr tới nơi stdout đang đi |
| `/dev/null` | Bỏ output                         |
| `< file`    | Lấy file làm stdin                |

# Phần 4 : cut - sort - uniq - wc

```bash
cut   # lấy cột
sort  # sắp xếp
uniq  # đếm dữ liệu trùng
wc    # thống kê số dòng/ từ/ ký tự
```

## 1. Tư duy tổng quát

ví dụ ta có log :

Failed password for root from 192.168.1.10
Failed password for admin from 10.0.0.5
Failed password for root from 192.168.1.10
Failed password for test from 10.0.0.5

Ta muốn trả lời : "IP nào xuất hiện nhiều nhất ?"

có thể nghĩ :

LOG
↓
lọc Failed password
↓
lấy IP
↓
sort
↓
uniq -c
↓
sort -nr

```bash
grep "Failed password" auth.log | cut ... | sort ... | uniq -c | sort -nr
```

## 2. cut

**cú pháp**

```bash
cut OPTION FILE
```

> lấy phần tôi cần trong mỗi dòng

**`cut -d` và `cut -f`**

`-d` => ký tự phân tách

`-f` => lấy field/cột nào

vd : alice:1001:1001:/home/alice:/bin/bash

các field được phân tách bởi `:` :

alice | 1001 | 1001 | /home/alice | /bin/bash

1 2 3 4 5

ví dụ :

```bash
echo "alice:1001:1001:/home/alice:/bin/bash" | cut -d: -f1
```

output : alice

giải thích :

> -f1 là lấy field số 1
> -d: là chia các field theo `:`

## 3. Lab với `/etc/passwd`

ubuntu có file : /etc/passwd

```bash
head /etc/passwd
```

output:

root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
...

lấy user :

```bash
cut -d: -f1 /etc/passwd # chia field theo : và lấy field 1
```

lấy nhiều field :

```bash
cu -d: -f1,7 /etc/passwd # chia field theo : rồi lấy field 1 và 7
```

## 4. `sort` - sắp xếp

**cú pháp**

```bash
sort FILE
```

ví dụ :

```bash
printf "banana\napple\norange\napple\n"
```

output

banana
apple
orange
apple

nếu :

```bash
print "banana\napple\norange\apple\n" | sort
```

thì output :

apple
apple
banana
orange

**`sort -r` - đảo ngược thứ tự**

```bash
printf "1\n5\n3\n2\n" | sort -r
```

output :

5
3
2
1

**`sort -n` - sắp xếp theo số**

```bash
prinf "1\n20\n10\n2\n" | sort
```

có thể có output :

1
10
2
20

> vì mặc định `sort` coi dữ liệu là text

nên nếu :

```bash
prinf "1\n20\n10\n2\n" | sort -n
```

sẽ có output là :

1
2
10
20

## 5. uniq - xử lý dữ liệu trùng

- `uniq` - dùng để xử lý các dòng liên tiếp giống nhau

ví dụ :

```bash
printf "apple\napple\nbanana\nbanana\nbanana\norange\n"
```

output :

apple
apple
banana
banana
banana
orange

nhưng nếu :

```bash
printf "apple\napple\nbanana\nbanana\nbanana\norange\n" | uniq
```

## 6. `uniq - c` - đếm số lần xuất hiện

`-c` = count

```bash
printf "apple\napple\nbanana\nbanana\nbanana\norange\n" | uniq -c
```

output

2 apple
3 banana
1 orange

> `uniq` thường đi với `sort`

**`uniq -c` + `sort -nr`**

> sắp xếp theo cái nào xuất hiện nhiều nhất đứng đầu

```bash
printf "apple\nbanana\napple\nbanana\napple\n" | sort | uniq -c | sort -nr
```

output :

3 apple
2 banana

## 7. `wc` - đếm

`wc` = word count

> nhưng không chỉ đếm word

các option quan trọng :

| option  | ý nghĩa |
| ------- | ------- |
| `wc -l` | số dòng |
| `wc -w` | số từ   |
| `wc -c` | số byte |

## 5. Initial Assessment

### Observation

Multiple failed SSH login attempts were observed from the IP
addresses 192.168.1.50, 10.10.10.20, and 172.16.0.15.

Notably, the source IP 172.16.0.15 generated multiple failed login
attempts followed by a successful login to the admin account.

### Why is it suspicious?

The repeated failed SSH login attempts are consistent with a
potential brute-force attack.

The successful login from 172.16.0.15 after multiple failed attempts
is particularly noteworthy and requires further investigation.
However, the available log data alone is not sufficient to determine
whether the successful login was authorized or resulted from
compromised credentials.

### What should be investigated next?

- Verify whether the login from 172.16.0.15 was authorized.
- Review the activity performed by the admin account after login.
- Verify the privileges assigned to the admin account.
- Check for system or configuration changes after the login.
- Review additional authentication and system logs.
- Monitor 172.16.0.15 for further suspicious activity.
