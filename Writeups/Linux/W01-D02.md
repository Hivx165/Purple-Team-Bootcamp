# Phần 1: Linux Filesystem Hierarchy

_Đây là kiến thức SOC dùng hằng ngày khi điều tra log, malware, persistence._

## 1.1 Linux Filesystem Hierarchy là gì?

Linux chỉ có một cây thư mục duy nhất, bắt đầu từ `/`.

```text
/ # root
├── /bin # lệnh cơ bản
├── /etc # config
├── /home # user
├── /var # log, data thay đổi
├── /tmp # file tạm
├── /usr # phần mềm
└── /dev # thiết bị
```

Tất cả mọi thứ đều nằm dưới `/`.

## 1.2 Những thư mục quan trọng nhất

### 1. /home

```text
/home/hieu2k5cht/
├── Desktop/
├── Documents/
├── Downloads/
├── Pictures/
├── Videos/
└── .bashrc
```

**Điểm quan trọng:**

Bạn có toàn quyền trong thư mục của mình:

- Tạo file
- Xóa file
- ...

Không thể truy cập `/home/user_khac` nếu không có quyền.

### 2. /etc

Đây là trái tim cấu hình của Linux.

SOC thường điều tra:

| File                   | Công dụng     |
| :--------------------- | :------------ |
| `/etc/passwd`          | User          |
| `/etc/shadow`          | Password hash |
| `/etc/hosts`           | Mapping IP    |
| `/etc/ssh/sshd_config` | SSH           |

**Chia nhóm để nhớ:**

#### Nhóm 1: User và quyền

```text
/etc/passwd # user
/etc/shadow # mật khẩu
/etc/group  # group
```

> **Ghi nhớ:** "Ai được vào máy"

#### Nhóm 2: Network

```text
/etc/hosts
/etc/resolv.conf
/etc/hostname
```

> **Ghi nhớ:** "Máy kết nối ra ngoài như nào"

#### Nhóm 3: System

```text
/etc/fstab
/etc/os-release
```

> **Ghi nhớ:** "Máy boot và nhận diện OS"

#### Nhóm 4: Service

```text
/etc/ssh/
/etc/nginx/
/etc/systemd/
```

> **Ghi nhớ:** "Dịch vụ này chạy ra sao"

### 3. /var

Đây là thư mục quan trọng nhất với Blue Team.

`/var` chứa dữ liệu thay đổi liên tục.

Đặc biệt: `/var/log` — bên trong có:

- `auth.log` (hoặc journal)
- `syslog`
- `apt.log`

**Purple Team note:**

| Vai trò       | Hành động                                 |
| :------------ | :---------------------------------------- |
| **Red Team**  | Xóa log để che dấu vết                    |
| **Blue Team** | Điều tra đăng nhập, phát hiện brute-force |

### 4. /proc

`/proc` = file ảo → phản ánh trạng thái hệ thống realtime.

> - Không phải file thật trên ổ cứng.
> - Là dữ liệu do kernel tạo ra khi chạy.

**Bên trong `/proc` có gì?**

#### a. Thông tin hệ thống

```text
/proc/cpuinfo # CPU
/proc/meminfo # RAM
/proc/uptime  # thời gian chạy
/proc/version # kernel version
```

Ví dụ:

```bash
cat /proc/cpuinfo
```

#### b. Thư mục theo PID (Process)

```text
/proc/1/
/proc/1234/
/proc/5678/
```

> Mỗi thư mục = 1 process đang chạy

Ví dụ: `/proc/$$` — process hiện tại

**Bên trong 1 process:**

```text
/proc/1234/
├── cmdline # lệnh chạy
├── status  # trạng thái
├── fd/     # file đang mở
```

**Đặc điểm quan trọng:**

1. Không chiếm dung lượng ổ đĩa.
2. Thay đổi liên tục theo thời gian thực.
3. Chỉ tồn tại khi hệ thống đang chạy.

**Ngắn gọn:** `/proc` = Cửa sổ nhìn vào bên trong kernel (realtime)

### 5. /dev

**Có thể hiểu:** `/dev` = thiết bị được biểu diễn như file.

> Trong Linux: mọi thứ = file, kể cả:
>
> - Ổ cứng
> - USB
> - Bàn phím
> - Màn hình

**Một số file quan trọng:**

#### a. Ổ đĩa

```text
/dev/sda  # ổ cứng chính
/dev/sda1 # phân vùng 1
/dev/sdb  # USB / ổ phụ
```

#### b. Terminal

```text
/dev/tty   # terminal hiện tại
/dev/pts/0 # terminal ảo
```

#### c. Special devices

```text
/dev/null   # "thùng rác" (ghi vào là mất)
/dev/zero   # tạo số 0 liên tục
/dev/random # random number
```

**Đặc điểm quan trọng:**

1. Không phải file thật.
2. Là interface để giao tiếp với hardware.
3. Có thể đọc/ghi như file bình thường.

**Nhớ nhanh:** `/dev` = DEVICE (phần cứng)

# Phần 2: Linux Permissions (Chi tiết)

## 2.1 Quyền truy cập (Permissions) là gì?

Linux là hệ điều hành **đa người dùng (Multi-user)**. Trên cùng một máy có thể tồn tại nhiều tài khoản, vì vậy hệ điều hành cần quyết định:

- Ai được đọc file?
- Ai được sửa file?
- Ai được chạy file?
- Ai được xóa file?

Ví dụ:

- Bạn có file `report.md`.
- Người khác có được chỉnh sửa không?
- Có được thực thi như chương trình không?

Linux giải quyết bằng **Permissions**.

### Lab 1: Kiểm tra quyền của file

Chạy lệnh:

```bash
ls -l
```

## 2.2 Phân tích kết quả của `ls -l`

Ví dụ:

```text
-rwxr-xr-- 1 hieu2k5cht hieu2k5cht 245 Sep 15 09:30 script.sh
```

Tách thành:

| Thành phần  | Ví dụ        | Ý nghĩa           |
| :---------- | :----------- | :---------------- |
| File Type   | `-`          | Loại file         |
| Permissions | `rwxr-xr--`  | Quyền truy cập    |
| Hard Links  | `1`          | Số liên kết cứng  |
| Owner       | `hieu2k5cht` | Chủ sở hữu        |
| Group       | `hieu2k5cht` | Nhóm              |
| Size        | `245`        | Kích thước (byte) |
| Date        | `Sep 15`     | Ngày sửa          |
| Name        | `script.sh`  | Tên file          |

### Ghi nhớ nhanh

```text
- rwx r-x r--
│ │   │   │
│ │   │   └── Others
│ │   └────── Group
│ └────────── Owner
└──────────── File Type
```

## 2.3 File Type (Ký tự đầu tiên)

Ký tự đầu tiên cho biết đối tượng đó là gì:

| Ký tự | Loại             |
| :---- | :--------------- |
| `-`   | File             |
| `d`   | Directory        |
| `l`   | Symbolic Link    |
| `c`   | Character Device |
| `b`   | Block Device     |

### Ví dụ

```text
drwxr-xr-x
```

Chữ `d` nghĩa là đây là **thư mục**.

### Lab 2: Phân biệt File và Directory

Chạy lệnh:

```bash
ls -l
```

Quan sát:

- File bắt đầu bằng `-`
- Thư mục bắt đầu bằng `d`

## 2.4 Ba nhóm quyền

Linux chia quyền thành **3 nhóm**:

```text
Owner      Group      Others
 rwx        r-x        r--
```

### Owner (Chủ sở hữu)

Thường là người tạo file.

Ví dụ:

```text
-rwx------
```

Owner có toàn quyền:

- Đọc
- Ghi
- Thực thi

### Group (Nhóm)

Nhiều người dùng có thể thuộc cùng một Group.

Ví dụ:

- `dev`
- `security`
- `admin`

Group có quyền riêng biệt.

### Others

Là tất cả những người không thuộc hai nhóm trên.

Ví dụ:

```text
777
```

Nghĩa là **mọi người đều có toàn quyền**.

> ⚠️ Đây là cấu hình rất nguy hiểm trong môi trường thật.

## 2.5 Ba loại quyền (r – w – x)

### Read (`r`)

- **Giá trị:** `4`
- **Cho phép:**
  - Mở file
  - Đọc nội dung

Ví dụ:

```bash
cat notes.txt
```

Nếu không có quyền đọc:

```text
Permission denied
```

### Write (`w`)

- **Giá trị:** `2`
- **Cho phép:**
  - Sửa nội dung
  - Ghi thêm dữ liệu

Ví dụ:

```bash
echo "Hello" >> notes.txt
```

### Execute (`x`)

- **Giá trị:** `1`
- **Cho phép:** Chạy chương trình

Ví dụ:

```bash
./script.sh
```

Nếu thiếu quyền thực thi:

```text
Permission denied
```

## 2.6 Cách tính quyền dạng số

Đây là phần quan trọng nhất.

| Quyền | Giá trị |
| :---- | :------ |
| `r`   | 4       |
| `w`   | 2       |
| `x`   | 1       |

### Ví dụ 1 – `7`

```text
rwx
```

Tính: `4 + 2 + 1 = 7`

### Ví dụ 2 – `5`

```text
r-x
```

Tính: `4 + 1 = 5`

### Ví dụ 3 – `6`

```text
rw-
```

Tính: `4 + 2 = 6`

## 2.7 Những quyền phổ biến

### Quyền `755`

```text
rwx r-x r-x
```

| Nhóm   | Quyền |
| :----- | :---- |
| Owner  | `rwx` |
| Group  | `r-x` |
| Others | `r-x` |

Thường dùng cho:

- Script
- Thư mục
- Chương trình

### Quyền `644`

```text
rw- r-- r--
```

Thường dùng cho:

- Markdown
- File cấu hình
- Tài liệu

### Quyền `700`

```text
rwx --- ---
```

Chỉ chủ sở hữu được truy cập.

Thường dùng cho:

- SSH
- Thư mục riêng

### Quyền `600`

```text
rw- --- ---
```

Thường dùng cho:

- Private Key
- Secret
- Password file

## 2.8 Lệnh `chmod`

`chmod` = **Change Mode**. Đây là lệnh thay đổi quyền.

### Cú pháp

```bash
chmod [permission] [file]
```

Ví dụ:

```bash
chmod 755 script.sh
```

### Phân tích lệnh

| Thành phần  | Ý nghĩa        |
| :---------- | :------------- |
| `chmod`     | Thay đổi quyền |
| `755`       | Quyền mới      |
| `script.sh` | File cần đổi   |

### Lab 3: Thay đổi quyền

- **Bước 1** — Tạo file:

```bash
touch demo.sh
```

- **Bước 2** — Xem quyền:

```bash
ls -l demo.sh
```

Ví dụ kết quả:

```text
-rw-r--r--
```

- **Bước 3** — Đổi quyền:

```bash
chmod 755 demo.sh
```

- **Bước 4** — Kiểm tra lại:

```bash
ls -l demo.sh
```

Kết quả:

```text
-rwxr-xr-x
```

## 2.9 `chmod` bằng ký hiệu

Ngoài dạng số còn có dạng ký hiệu.

### Thêm quyền chạy

```bash
chmod +x demo.sh
```

Nghĩa là: Thêm quyền Execute.

### Một số ví dụ

| Lệnh             | Ý nghĩa               |
| :--------------- | :-------------------- |
| `chmod +x file`  | Thêm Execute          |
| `chmod -w file`  | Bỏ quyền Write        |
| `chmod u+x file` | Execute cho Owner     |
| `chmod g-w file` | Bỏ Write của Group    |
| `chmod o+r file` | Cho Others quyền Read |

### Khi nào dùng?

Trong thực tế:

```bash
chmod +x scan.sh
```

Được dùng rất nhiều khi chạy script Bash hoặc Python.

## 2.10 Lệnh `chown`

`chown` = **Change Owner**. Dùng để đổi chủ sở hữu.

### Cú pháp

```bash
sudo chown user:group file
```

Ví dụ:

```bash
sudo chown hieu2k5cht:hieu2k5cht demo.sh
```

### Giải thích

| Thành phần | Ý nghĩa        |
| :--------- | :------------- |
| `sudo`     | Quyền quản trị |
| `chown`    | Đổi chủ sở hữu |
| `user`     | Chủ mới        |
| `group`    | Nhóm mới       |

### Lab 4: Kiểm tra Owner

Chạy lệnh:

```bash
ls -l demo.sh
```

Quan sát Owner và Group.

## 2.11 Lệnh `chgrp`

`chgrp` chỉ đổi Group.

Ví dụ:

```bash
sudo chgrp security demo.sh
```

So sánh:

| Lệnh    | Chức năng                       |
| :------ | :------------------------------ |
| `chown` | Đổi Owner (và có thể đổi Group) |
| `chgrp` | Chỉ đổi Group                   |

## 2.12 `umask`

`umask` quyết định quyền mặc định khi tạo file mới.

### Kiểm tra

```bash
umask
```

Ví dụ kết quả:

```text
0022
```

### `umask` hoạt động thế nào?

File mới mặc định có quyền:

```text
666
```

`umask` sẽ loại bỏ quyền. Ví dụ:

```text
  666
- 022
-----
  644
```

Đó là lý do file mới thường có:

```text
rw-r--r--
```

### Lab 5: Quan sát quyền mặc định

Chạy lệnh:

```bash
umask
touch default.txt
ls -l default.txt
```

Quan sát quyền của `default.txt`.

## 2.13 Những lỗi thường gặp

### Lỗi 1 – Permission denied

```text
Permission denied
```

- **Nguyên nhân:**
  - Thiếu `x`
  - Thiếu `r`
- **Khắc phục:**

```bash
chmod +x file
```

### Lỗi 2 – Operation not permitted

```text
Operation not permitted
```

- **Nguyên nhân:**
  - Không phải Owner
  - Không có quyền quản trị
- **Khắc phục:**

```bash
sudo chown ...
```

### Lỗi 3 – Dùng `777`

```bash
chmod 777 file
```

Đây là thói quen rất nguy hiểm. Không nên dùng trừ môi trường thử nghiệm.

# Phần 3: SUID, SGID và Sticky (Special Permissions)

## 3.1 Special Permissions là gì?

Có 3 quyền cơ bản:

- `r` : Read
- `w` : Write
- `x` : Execute

Còn có 3 quyền đặc biệt:

| Quyền      | Ký hiệu | Giá trị |
| :--------- | :------ | :------ |
| SUID       | `s`     | 4000    |
| SGID       | `s`     | 2000    |
| Sticky Bit | `t`     | 1000    |

Điểm khác biệt:

- `rwx` kiểm soát quyền truy cập.
- Special Permissions thay đổi cách chương trình hoạt động khi được thực thi.

## 3.2 SUID (Set User ID)

**Là gì?**

> SUID cho phép một chương trình chạy với quyền của chủ sở hữu thay vì quyền của người đang chạy nó.

**Mô hình hoạt động:**

```text
User thường ------- passwd (SUID) ------- Quyền Root
```

- Nếu không có SUID:

```text
User -> passwd -> Permission denied
```

- Có SUID:

```text
User -> passwd (chạy bằng quyền root) -> đổi mật khẩu thành công
```

**Cách nhận biết SUID:**

> Chữ `s` xuất hiện ở vị trí `x` của User.

**Khi nào xuất hiện `s` và `S` (chữ hoa):**

| Hiển thị     | Ý nghĩa                        |
| :----------- | :----------------------------- |
| `s` (thường) | Có SUID và Execute             |
| `S` (hoa)    | Có SUID nhưng không có Execute |

### Lab 1: Quan sát SUID

Chạy lệnh:

```bash
ls -l /usr/bin/passwd
```

Ghi lại:

- Owner: **root**
- Group: **root**
- Chữ `s` nằm ở đâu: **-rws r-x r-x**

### Tìm toàn bộ file SUID

```bash
find / -perm -4000 2>/dev/null
```

Thành phần trong lệnh và ý nghĩa:

| Thành phần  | Ý nghĩa             |
| :---------- | :------------------ |
| `find`      | Tìm file            |
| `/`         | Bắt đầu thư mục gốc |
| `-perm`     | Lọc theo quyền      |
| `-4000`     | Có bit SUID         |
| `2>`        | Chuyển luồng lỗi    |
| `/dev/null` | Bỏ thông báo lỗi    |

**Luồng dữ liệu:**

```text
find ---- kiểm tra quyền ---- hiển thị file SUID
```

- Nếu bỏ `2>/dev/null` thì sẽ hiển thị thêm hàng trăm dòng `Permission denied`.

## 3.3 SGID (Set Group ID)

**Là gì?**

> SGID khiến chương trình chạy với quyền Group.

Ví dụ: `-rwx r-s r-x` → `s` nằm ở vị trí `x` trong group.

**Minh họa:**

```text
User ---- Program (SGID) ---- Quyền Group
```

**SGID trên thư mục:**

> Đây là nơi mà SGID được dùng nhiều.

Ví dụ: `drwxrwsr-x`

Ý nghĩa: File mới tạo bên trong sẽ tự động thuộc cùng group.

### Lab 2: Quan sát SGID

```bash
find / -type d -perm -2000 2>/dev/null | head
```

| Thành phần    | Ý nghĩa               |
| :------------ | :-------------------- |
| `-type d`     | Chỉ tìm thư mục       |
| `-perm -2000` | Có SGID               |
| `head`        | Hiển thị vài dòng đầu |

## 3.4 Sticky Bit

> Đây là đặc quyền dễ gặp nhất.

Ví dụ: `drwxrwxrwt` — thấy `t` xuất hiện ở cuối.

**Sticky giải quyết vấn đề gì?**

Giả sử có thư mục chung: `/tmp`

- Nếu không có Sticky Bit:
  - User A tạo file
  - User B xóa được
  - => Nguy hiểm
- Sticky Bit khiến cho:
  - Ai cũng tạo được file
  - Chỉ chủ file mới xóa được file

### Lab 3: Kiểm tra /tmp

Chạy lệnh:

```bash
ls -ld /tmp
```

Kết quả:

```text
drwxrwxrwt 25 root root 16384 Sep 16 01:37 /tmp
```

## 4.2 Cách Red Team sử dụng SUID

Sau khi có shell, pentester thường làm theo quy trình:

```text
Shell ------ find -4000 ------ GTFOBins ------ Privilege Escalation
```

1. Có shell
2. Liệt kê SUID
3. Đối chiếu GTFOBins
4. Nếu binary có kỹ thuật khai thác → leo thang đặc quyền

**Ví dụ:**

Nếu quản trị viên vô tình gán SUID cho `vim`, thì `vim` có thể bị lạm dụng để mở shell với quyền root.
